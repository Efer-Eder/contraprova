# O que o projeto não é

Seção 27 do [manifesto](../manifesto.md), organizada em lista. Serve de limite de escopo: uma proposta que dependa de algo listado aqui precisa de [RFC](../rfcs/README.md) que justifique a mudança do manifesto.

## Não é apenas

- um gerador de testes;
- um revisor de código;
- um scanner de vulnerabilidades;
- um agente de programação;
- um painel de métricas.

Isso não impede que o produto tenha partes que façam algo parecido; significa que nenhuma delas, sozinha, define o projeto.

## Não é uma promessa de

- ausência de bugs;
- substituto universal de especialistas;
- certificação automática de segurança.

A seção 2 reforça: o produto não promete software sem bugs, e sim não confundir ausência de evidência de erro com evidência de funcionamento.

## Não deve

- exigir que todos os projetos usem a mesma arquitetura;
- modificar código, instalar componentes, enviar dados ou publicar versões sem as permissões necessárias;
- transformar a desconfiança em rejeição automática de todo código existente. O objetivo é verificar, não condenar sem evidência.

## Consequências para este repositório

- Nenhum documento pode afirmar que o Contraprova garante, certifica ou elimina falhas.
- Nenhum documento pode apresentar o projeto como produto pronto: hoje existe apenas especificação.
- A documentação de contribuição (veja [agentes](../agentes/README.md)) trata código gerado por IA com a mesma desconfiança construtiva do manifesto: verificar, não condenar.
